### [1.2.0](https://github.com/semhoun/slim-tracy/compare/1.1.0...1.2.0)

> 9 November 2026

#### Breaking Changes

- Require PHP 8.2 through 8.5 and Slim 4.15.3 or later within Slim 4.
- Remove native Tracy AJAX interception, even when the new API profiler is
  disabled. There is no native fallback or automatically added `X-Tracy-Ajax`
  header. See the [migration guide](README.md#ajaxapi-profiling-migration).
- Replace global debugging shortcuts and `shortcuts.php` with autoloaded
  `SlimTracy\Debug` methods and `SlimTracy\ConsoleLevel` values. Some public
  classes are now final; use composition instead of extending them.
- Read profile measurements through typed accessors and configure console
  integrations through their constructors. Pass the raw JSON body to
  `execute($rawBody)` instead of populating HTTP globals. See the
  [API migration guide](README.md#api-migration).
- Restrict Tracy to the tested 2.12.2 integration. Construct the middleware
  before any `Debugger::enable()` call that can serve assets.

#### Added

- Opt-in API profiling for development, with correlated server and browser
  timings, memory usage, Doctrine/Eloquent queries, manual profiles, and Twig
  measurements when their integrations are available.
- A shared, temporary request history with non-destructive reads, expiration,
  configurable count and size limits, and explicit truncation markers.
- An API panel and a dedicated debug page containing only that panel, plus
  explicitly registered endpoints for history, profile details, and
  client-reported timings.
- An independent `@slim-tracy/ajax-profiler` package with a common fetch/XHR
  client for Twig, React, and separately hosted applications. Includes origin
  allowlists, abort/error reporting, bounded local history, SSR-safe imports,
  and stop/HMR cleanup.
- An optional Vue Devtools adapter with a request timeline and inspector,
  including correlated server details, using the public Devtools plugin API.

#### Improved

- API collection works with `ShowBar=false` and independently of panel-selection
  cookies. Doctrine collection no longer requires its panel to be selected when
  API profiling is active.
- Ordinary API calls avoid Tracy's native cookie-session lock, allowing
  concurrent requests sharing a cookie while preserving native deferred loading
  for HTML documents.
- Preserve application request arguments, credentials, response streams, status
  codes, and Slim-handled JSON errors. Fetch instrumentation does not consume
  response bodies.
- Support Slim base paths consistently across debug routes, native-dispatch
  guards, profiling exclusions, and browser endpoint URLs.
- Update dependency compatibility and migration examples for current Slim,
  Doctrine, Twig, and Eloquent integrations.

#### Fixed

- Prevent earlier requests' collector entries from appearing in subsequent
  snapshots when the profiler instance is reused.
- Preserve profile expiration when browser timings arrive; client updates cannot
  extend retention.
- Handle XHR reuse, concurrent requests, late Vue Devtools connections, and
  repeated client installation without duplicate interception.
- Make profiler routes compatible with writable Slim containers and prevent
  inactive panels from continuously polling.

#### Security

- Restrict JSON-RPC calls to public application methods and escape browser
  console values that could terminate a script element.
- Require explicit activation and resolved Tracy development mode for collection
  and every profiler endpoint. Disabled and production modes cannot expose
  residual profiles or native deferred host panels through the debug page.
- Keep stored profiles outside the web root with restrictive permissions and
  atomic writes. Exclude request bodies, query strings, cookies, authorization
  headers, and SQL bindings from default exports; provide a host SQL filter for
  sensitive literals in raw statements.
- Apply exact-origin CORS checks to profiler endpoints and render untrusted
  profile data as text rather than HTML.
- Profiling remains unauthenticated and shared across users and sessions. Use it
  only on a protected development network; CORS is not authentication and raw
  SQL may still contain sensitive values.
